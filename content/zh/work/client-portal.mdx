## 背景

以前俱乐部订了定制队服之后，只能发邮件问进度：设计稿批了没有、报价单在哪、什么时候发货。每个问题都要销售去 CRM 里查一遍才能回答。下单表单、审批和设计稿散在不同的地方，各有各的链接。

## 难点

- **一切以 CRM 为准。** 商机阶段、报价和联系人本来就都在 CRM 里，门户不能变成第二个数据库。
- **不要密码。** 负责队服的人每个赛季都可能换，所以只凭邮箱就得能登录。
- **两个品牌。** 同一个门户要服务不止一个品牌，每个品牌有自己的外观。

## 我的分工

方案是我写的。门户的第一版是我搭的（登录、首页概览、订单列表、订单详情），原来的下单表单也是我迁进来的。之后大部分功能由另一位工程师接着开发，我负责集成和 n8n 这一侧。

## 架构

- **前端**：React 19、TypeScript、Vite、Tailwind 加 shadcn；服务端数据用 TanStack Query 管理，页面路由用 React Router。
- **登录**：给邮箱发一个六位验证码，由工作流校验，登录状态保持 30 天。
- **订单**：进度阶段直接对应 CRM 里的商机阶段，客户在门户里看到的和销售看到的一模一样。
- **下单表单**：分几步填（基本信息、尺码、选产品、确认），可以上传设计稿、确认报价，确认后会生成一份带签名的确认文件。
- **后端**：没有自己的后端。每一次读写都是一个 n8n Webhook，由它去和 CRM 打交道。
- **Mock 模式**：准备了一整套假数据，整个门户可以在本地脱离后端跑起来，方便演示和评审。

## 三个关键决定

**1. 用 Webhook 代替 API 服务器。** 公司的运营流程本来就跑在 n8n 上。门户的后端也放在那里，运营团队不用等发版，就能看到、也能改每一步。

**2. 直接显示 CRM 的阶段，不另造一套状态。** 如果另外设计一套更好看的状态，就得维护两套并让它们保持一致。直接用现有的阶段，门户显示的就永远是真实进度。

**3. 一开始就做 mock 模式。** 每个页面都能在没有后端的情况下用假数据显示出来。这样演示不会翻车，设计评审很快，另一位工程师开发时也不用碰线上数据。

## 结果

- 负责队服的人自己就能看到每张订单和当前进度，不用再发邮件问销售。
- 下单、设计稿、报价和确认都在一个地方，登录一次就能全部搞定。
- 门户上线，没有多出任何一台要运维的服务器。

## 复盘

应该先把 Webhook 的接口格式定成前后端共用的类型化 schema，再开始写页面。不然工作流里改了一个字段名，只有等到运行时才会发现。

## 技术栈

React 19、TypeScript、Vite、Tailwind、shadcn、TanStack Query、React Router、react-hook-form、Zod、n8n、Zoho CRM、Cloudflare Pages。
