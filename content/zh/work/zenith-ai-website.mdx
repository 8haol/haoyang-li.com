## 背景

Zenith AI 提供 AI 系统、网站开发、系统集成和增长服务。第一版官网是在低代码工具上快速拼出来的，看上去和其他 agency 的网站没什么两样。新网站要在最初几秒内就让访客看出来：这个团队做东西是用心的。

## 约束

- **动效不能卡。** 网站大量依赖滚动动画和 WebGL，但在中端笔记本和手机上，依然要做到即时响应。
- **先保证可读。** 访客是企业主，不是设计师。每个板块都要先把 Zenith 做什么讲清楚，再去炫技。
- **只有我一个人。** 设计、大部分文案结构和开发，都由我一个人完成。

## 我的角色

全部包办：艺术指导、版式布局、动效系统、Three.js 场景、内容结构、联系表单链路和部署。

## 架构

- **Next.js 15 和 React 19**，能静态渲染的地方都静态渲染。
- **Lenis** 负责平滑滚动，**GSAP ScrollTrigger** 负责 pin 住和随滚动 scrub 的板块，两者共用一个时钟，永远不会错位。
- **Three.js** 按需加载，只出现在用到它的路由上，首屏绘制从不需要等 3D bundle。
- **联系表单**提交到一个 route，通过 Resend 发出邮件，也可以按需经 webhook 转发到 CRM。
- **CI** 跑在 GitHub Actions 上，负责 lint、类型检查和构建；站点通过 Cloudflare 对外提供服务。

## 三个决策

**1. 一个隐喻，贯穿始终。** 整个网站讲的是一次攀登：海拔标记、不断爬升的首屏、像登山阶段一样的各个板块。只有一个核心概念，每个设计选择就都有了可以检验的标准。

**2. 3D 只花在值得的地方。** WebGL 按路由做 code splitting，并且等文字渲染到屏幕上之后才启动。在任何 3D 加载之前，页面就已经可以阅读。

**3. 动效跟着滚动走，而不是跟着计时器走。** 动画由滚动位置 scrub 驱动，所以永远和读者正在看的内容同步；开启“减少动态效果”时，会退化为静态布局。

## 成果

- 已在 zenithai.one 上线，取代了早先的低代码版本。
- 网站本身就展示了团队所卖的做工品质，而不是靠文字去描述。
- 维护很轻：一个代码仓库加 CI，没有需要时时照看的 CMS。

## 如果重来

从第一个 commit 起就在 CI 里设好性能预算。自动检查 bundle 体积和长任务，重量级依赖在引入当天就能被发现，而不是拖到最后手动排查时才暴露。

## 技术栈

Next.js、React、TypeScript、GSAP、Lenis、Three.js、Resend、GitHub Actions、Cloudflare。
