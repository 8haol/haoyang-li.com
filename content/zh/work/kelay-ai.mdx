## 背景

在英国，华人开的餐馆、按摩店、美甲店和宠物美容店，经常因为大家都在忙而漏接电话，漏一个电话就可能丢一单生意。市面上的电话机器人只会说英语，话术千篇一律，配置还得找开发人员。Kelay 想做的，是一个填几张表就能用起来的电话前台。

## 难点

- **老板不懂技术。** 设置只能是一步步的向导，不能让人改配置文件；正式上线前，老板还要能亲耳听听 Agent 讲得怎么样。
- **到处都会重试。** 电话服务商的 Webhook 会重发，所以保存通话记录必须防重复：同一个事件处理两遍，也只能留下一条记录。
- **两种语言。** 很多来电的客人更习惯说普通话，同一个 Agent 必须中英文都能应付。
- **两个创始人，没有融资。** 在试点客户开始付钱之前，用到的每项服务都得有免费额度。

## 我的分工

技术上的事都是我做：多租户数据模型、登录认证、设置向导、自动创建 Retell Agent、Agent 用到的各个工具、Webhook 处理、订阅计费、商户后台，还有为了调 Agent 打的大量测试电话。

## 架构

- **租户**：每个商户在 PostgreSQL（Drizzle）里有自己的门店、服务项目、员工、营业时间和预约日历。不同行业有对应的模板（`verticals`），会先填好一套合理的默认值。
- **设置向导**：收集商户信息，填完后自动创建一个 Retell Agent，生成好 prompt，配好工具。上线前，商户可以先在浏览器里打一通测试电话。Twilio 号码开通功能已经做好，还在等第一次正式使用。
- **工具**：Agent 可以查空档、预约、改约或取消、查已有预约，餐厅还可以查空桌和订座。每个工具都是一个 HTTP 接口，Agent 调用时带上共享密钥。
- **通话记录**：录音、文字稿和通话结果按通话保存，以 Retell 的 call ID 为主键做 upsert，Webhook 重发多少次都只有一条记录。
- **计费**：用 Stripe 做订阅和通话分钟数充值。Agent 的指令里写死了绝不在电话里收钱；收定金的功能已经排进计划。

## 三个关键决定

**1. Agent 从数据生成，不靠手工配置。** Agent 的 prompt、声音和可用的工具，都根据商户的资料自动生成。营业时间一改，Agent 会跟着重新生成。正因为这样，开通 Kelay 才只是填几张表，而不是一个要人来实施的项目。

**2. 在会重试的地方做防重复。** 电话服务商会重发 Webhook。通话记录以服务商的 call ID 为主键做 upsert，同一个事件来两遍也不会出问题。一条规则，就把重复记录这一整类 bug 都消灭了。

**3. 按实际延迟选模型。** 早期打测试电话时，Agent 反应明显偏慢。我在真实通话里对比了几个模型的响应速度，最后留下了更快的 GPT-4.1，而不是纸面参数更好的新模型。在电话里，停顿一两秒，对方就以为断线了。

## 结果

- 已经可以开始试点：商户坐下来一次，就能完成注册、设置好 Agent，并通过测试电话听到效果。第一批目标客户是餐馆。
- 一个 Agent 同时应付英语和普通话。
- 预约、改约、取消和订座都能在电话里办完，不需要人插手。

## 复盘

应该一开始就做一个通话重放工具。能把录好的电话拿出来，对着新版的 prompt 或工具离线重放一遍，可以省下好几天打测试电话的时间。以后再做语音产品，我会先做这个。
