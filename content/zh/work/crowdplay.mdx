## 背景

当时我在帮忙办一场国际学生迎新活动：五十人左右，七个活动站点，分队计分，最后还要颁奖。这种活动一般靠纸卡片加一张表格，结果就是到处排队、卡片丢了，也没人知道哪队领先。我想让整个场地玩起来像同一场游戏。

## 难点

- **只靠手机。** 来宾不用装任何东西，扫二维码就能玩，在微信里打开也要能用。
- **志愿者和 Wi-Fi 都不稳。** 一晚上工作人员会换好几拨，网络断了再连上，分数也不能丢、不能重复记。
- **只有一个晚上。** 线下活动没有重来的机会。

## 我的分工

全部是我做的：玩法设计、界面、数据库和里面的函数、投影画面、管理后台，还有活动当晚的现场支持。

## 架构

- **来宾端**：扫码加入，拿到一个三位数编号；主持人宣布开始之前，等待页会显示他们的护照卡。
- **工作人员端**：输入六位数代码，就能在站点给整队打分，不需要注册账号。
- **投影端**：实时显示各队进度、活动动态、签到墙和颁奖环节。
- **管理端**：管理主办方、活动和站点库，上面还有一层给平台所有者用的视图。
- **后端**：Supabase Postgres，开了行级安全。每个游戏操作都是一个 SECURITY DEFINER 函数，带防重复的 key，所以请求重发也不会重复计分。各个屏幕每三秒刷新一次。
- **媒体**：主办方的照片和视频相册存在 Cloudflare R2 上，通过 edge function 生成的签名链接访问。

## 三个关键决定

**1. 数据库就是游戏引擎。** 规则写进 Postgres 函数之后，测试只用盯一个地方，不用部署服务器，所有客户端拿到的保证也都一样。

**2. 定时刷新，不用实时推送。** 五十部手机在场馆 Wi-Fi 上反复断开重连 websocket，这种问题我不想在活动当晚碰到。每三秒拉一次数据很朴素，但结果可预期。

**3. 主题就是一份配置。** 文案、印章和站点名称都来自主题配置，所以中秋版完全复用了这套引擎，只换了外观。

## 结果

- 迎新活动从头到尾都用它来跑，分数实时显示在投影上，最后的颁奖也在投影上进行。
- 请求重发不会出问题：每一次打分都做了防重复。
- 已经开源，还加了一套中秋主题。

## 复盘

写代码的同时就应该把志愿者指南写好。活动当晚，一句清楚的操作说明比多一个功能有用得多。

## 技术栈

React 19、TypeScript、Vite、Tailwind、React Router、Supabase（Postgres、RLS、RPC、Edge Functions）、Deno、Cloudflare R2、Netlify。
